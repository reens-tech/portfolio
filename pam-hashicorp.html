🏗️ What is HashiCorp Vault?

HashiCorp Vault is an open-source secrets management system designed for:

  • Storing sensitive data (database passwords, API keys, tokens)
  • Managing authentication credentials for applications
  • Automating credential rotation and lifecycle management
  • Providing audit trails for compliance

Key Principle: Never Hardcode Secrets

Instead of embedding credentials in code, configuration, or logs, applications request them from Vault at runtime. This keeps secrets:

  • Out of source code repositories
  • Out of CI/CD logs and build artifacts
  • Encrypted at rest
  • Audited for access
  • Easily rotatable without code changes
✓ Vault vs. Password Managers: Password managers like 1Password or LastPass are designed for humans to retrieve credentials. Vault is designed for applications and automation to request and use secrets programmatically.

💼 Common Use Cases

Application Secrets

Store database passwords, API keys, and service credentials that applications need at runtime.

Certificate Management

Generate and rotate TLS/SSL certificates for services and applications.

Automated Password Rotation

Vault can automatically rotate database passwords and service account credentials on a schedule.

CI/CD Integration

Inject secrets into build pipelines without exposing them in logs or configuration.

Infrastructure as Code

Provide secrets to Terraform, Ansible, CloudFormation, and other IaC tools securely.

Microservices Authentication

Service-to-service authentication using dynamically generated credentials.

🔐 Authentication Methods

Vault supports multiple authentication mechanisms:

Token Authentication

Vault generates tokens that applications use to authenticate. Tokens can have expiration times and be revoked.

Directory Service (LDAP/AD)

Use your team's directory to log in. Works for both individual accounts and service accounts.

AppRole

Purpose-built authentication for applications and automation. Each application gets a RoleID and SecretID.

Kubernetes

Native Kubernetes integration. Pods authenticate using service accounts.

Cloud Provider Methods

AWS IAM, Azure MSI, GCP Service Accounts—authenticate using cloud-native identities.

OIDC / JWT

Use external identity providers like Okta, Auth0, or any OIDC-compliant provider.

🔄 Dynamic Secret Rotation

Static Secrets (Traditional)

A password is stored in Vault and manually rotated by an administrator.

  • ✗ Long-lived credentials increase breach risk
  • ✗ Manual rotation is error-prone
  • ✗ Hard to track who has access

Dynamic Secrets (Modern)

Vault generates unique, temporary credentials for each application request.

  • ✓ Credentials are short-lived (minutes to hours)
  • ✓ Automatic rotation—no manual effort
  • ✓ Each credential is unique—easier to track and revoke
  • ✓ Better audit trail

How It Works

  1. Application requests a credential from Vault
  2. Vault connects to the target system (database, API, etc.)
  3. Vault generates a unique username/password
  4. Vault sets this credential on the target system
  5. Vault returns the credential to the application with TTL (time-to-live)
  6. Application uses the credential for the duration of the TTL
  7. Vault automatically revokes the credential when TTL expires
✓ Best Practice: When possible, use dynamic secrets instead of static long-lived passwords. This significantly reduces the window of exposure if a credential is compromised.

🏗️ Vault Architecture

Core Components

  • Vault Server: The core service that stores and manages secrets
  • Storage Backend: Where encrypted secrets are persisted (file, database, cloud storage)
  • Auth Methods: How clients authenticate and receive tokens
  • Secret Engines: Plugins that handle different types of secrets
  • Audit Logs: Records of all API requests for compliance

Deployment Options

  • Standalone: Single Vault server (suitable for development)
  • HA Cluster: Multiple Vault nodes sharing storage for high availability
  • Cloud-Managed: Vault as a managed service (HCP, AWS Secrets Manager, Azure Key Vault)

Security Features

  • Encryption at rest using industry-standard algorithms
  • Encryption in transit using TLS
  • Audit logging of all secret access
  • Automatic unsealing (for HA deployments)
  • Rate limiting and access policies
✓ Planning: When deploying Vault, consider your team's uptime requirements, backup strategy, compliance needs (HIPAA, PCI-DSS, SOC 2), and audit log retention policies.

🔗 Integration Platforms

Kubernetes & Containers

Native Kubernetes integration via service accounts. Pods can automatically authenticate and retrieve secrets.

CI/CD Platforms

  • GitLab CI/CD - Inject secrets into pipeline jobs
  • Jenkins - Use Vault plugin for credential retrieval
  • GitHub Actions - Retrieve secrets during workflow execution
  • HashiCorp Nomad - Native integration

Infrastructure as Code

  • Terraform: Vault provider for dynamic secret retrieval
  • Ansible: Lookup plugin for fetching secrets
  • CloudFormation: Integration with AWS Vault

Application Integration

  • SDKs for most programming languages
  • HTTP REST API for custom integrations
  • Environment variable injection
  • Configuration file generation
