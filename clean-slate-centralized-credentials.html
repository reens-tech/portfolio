🌐 Centralized Authentication & Credentials

AAA Systems & Network Device Management

Overview of centralized authentication systems (RADIUS, TACACS+, LDAP) and how they manage credentials across network devices and infrastructure. For educational purposes.

🔐 Centralized Authentication Systems

Centralized authentication, authorization, and accounting (AAA) systems are critical infrastructure components that manage access to network devices. Unlike local device accounts, centralized systems provide:

  • Single source of truth for user/service account credentials
  • Unified password policies and rotation schedules
  • Comprehensive audit logging of access attempts
  • Ability to revoke access immediately across all devices
  • Compliance with security standards (HIPAA, PCI-DSS, SOC 2)

Common AAA Protocols

Protocol Purpose Use Case
TACACS+ Terminal Access Control Network device logins (routers, switches, firewalls)
RADIUS Remote Access Dial-In User Service VPN access, WiFi authentication, remote access servers
LDAP Lightweight Directory Access Protocol Directory services, user accounts, group membership
✓ Best Practice: Modern organizations use directory services (LDAP, Active Directory) as the central repository for credentials, with TACACS+/RADIUS as the access control layer for network devices.

🔄 Credential Rotation for AAA Systems

Static Service Accounts

Service accounts used for infrastructure automation (Ansible, Terraform, monitoring tools) must have their passwords rotated periodically:

  • Typical rotation cycle: 90 days for critical accounts, 180 days for standard accounts
  • Documentation must be updated with new credentials
  • All systems using that credential must be updated simultaneously
  • Change windows should be scheduled for low-impact times

Automation Considerations

When rotating credentials used by automation tools, coordinate with:

  • Configuration management systems (Ansible, Puppet, Chef)
  • CI/CD pipelines and scheduled jobs
  • Monitoring and alerting systems
  • Log aggregation and analysis tools

Rotation Process

  1. Schedule rotation during maintenance window
  2. Generate new password (use strong, random generation)
  3. Update in central credential store (Vault, password manager)
  4. Update in all systems using that credential
  5. Test all systems function correctly
  6. Monitor for access issues or failures
  7. Document completion and next rotation date
✓ Documentation: Keep a credential rotation log that tracks: credential name, rotation date, next scheduled rotation, who performed it, and any issues encountered.

📋 Network Device Credentials

Local Device Accounts vs. Centralized Auth

Aspect Local Device Accounts Centralized Authentication
Storage Stored on each device individually Stored in central directory (LDAP/AD)
Rotation Must be changed on each device separately Changed once; applies to all devices
Audit Trail Per-device logs (dispersed) Centralized logging and monitoring
Revocation Must remove from each device Immediate across all systems

Common Network Device Types

  • Routers & Switches: Cisco IOS, Juniper JunOS, Arista
  • Firewalls: Palo Alto, Fortinet FortiGate, Checkpoint
  • Load Balancers: F5, Citrix NetScaler
  • Console Servers: IPMI, iLO, iDRAC interfaces

Security Best Practices

  • Use separate credentials for different roles (read-only, admin, service accounts)
  • Enable command logging for all privileged access
  • Implement IP whitelisting where possible
  • Use SSH keys instead of passwords for automation (where supported)
  • Monitor for failed login attempts and unauthorized access
  • Schedule maintenance windows for credential updates

📊 Audit & Compliance

What Should Be Audited?

  • All successful and failed authentication attempts
  • Configuration changes (who made them, when, what changed)
  • Credential rotation dates and personnel involved
  • Access to sensitive commands or configurations
  • Privilege escalation attempts

Retention & Analysis

  • Store AAA logs for minimum 90 days (many compliance standards require 1+ year)
  • Use centralized log aggregation (ELK, Splunk, Datadog)
  • Set up alerts for suspicious patterns (brute force, unusual access times)
  • Generate monthly compliance reports
  • Archive for incident investigation and forensics
✓ Compliance Standards: HIPAA, PCI-DSS, SOC 2, and ISO 27001 all require comprehensive AAA audit logging and documentation of credential management practices.
